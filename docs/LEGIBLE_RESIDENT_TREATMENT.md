# Legible resident treatment v1

`legible-resident-v1` is a versioned behavioral treatment for sustained resident
life through the ordinary human-comparable semantic Minecraft body. It is not a
neutral benchmark and it is not the existing coached `resident-v1` product
policy. Its first live Oxford acceptance did not establish improvement: Phi
made two public camera commitments, Llama made no valid action, and neither
resident adapted when hostile ecology arrived.

## Standing charter

The system prompt establishes only these durable premises:

- the resident has a persistent identity in its own lived trajectory and public
  commitments;
- it directs its own conduct from current perception and its own continuity;
- it attends to its body, environment, and other residents as independent
  beings;
- it adapts to authoritative Minecraft outcomes and does not promote an
  expectation or unseen result into fact; and
- before one action it publishes a short intention and expected observable
  consequence as public continuity, never private reasoning.

The charter supplies no task, survival objective, project, material priority,
social objective, action recommendation, navigation conclusion, or recovery
strategy. The controller exposes the same
`minecraft-human-semantic-v1` observation and action profiles and
`vanilla-player-v1` risk profile ratified for human-comparable embodiment.

## Exact response boundary

For the current local implementation the treatment requires the v2 strict
response boundary. A one-shot process may use
`behold.ollama-local-json-action.v2`; a continuing local life may instead use
`behold.ollama-local-resident-session.v1`. Both expose the same exact
`behold.ollama-local-json-action-schema.v2` response:

```json
{
  "intention": "one public line, 1-240 characters",
  "expectedObservableConsequence": "one public line, 1-240 characters",
  "action": "one exact admitted action name",
  "arguments": {}
}
```

Each action alternative preserves the canonical action input schema and rejects
additional top-level response fields. The contract message binds
`policyProfile: legible-resident-v1`, the body/action/safety profiles, every
admitted action schema, any physically required action, and the v2 response
protocol. The per-attempt identity continues to bind the exact transport,
schema digest, installed template digest, model tag/content digest, action
contract, and response format.

The resident-session transport makes the charter and current admitted control
contract the first two messages, ahead of changing experience. It records the
exact prefix digest; that identity does not claim the runtime reused a KV
cache. Every admitted model is loaded while Minecraft ticks remain frozen,
all configured model digests must then be simultaneously present, and only the
loads created by that setup are unloaded after cognition drains. These setup
operations are explicit lifecycle evidence, not resident decisions or hidden
quota use.

Behold accepts neither whitespace repair nor tolerant field normalization. It
makes no correction request and no retry. The original controller action-schema
validator remains the final boundary before an intent can exist. A malformed
commitment or action consumes its attempt as an explicit malformed output.

## Durable and readable continuity

An accepted response becomes
`behold.resident-public-action-commitment.v1`. Behold deterministically renders
it as:

```text
Intention: <intention>
Expected observable consequence: <expectedObservableConsequence>
```

The structured commitment and that exact public rendering persist together in
the resident's authoritative EntityTurn. The turn already binds the resident,
model, policy/body/action/safety profiles, release, model-facing observation,
proposed action, authenticated outcome, and next observation in the Lync causal
history. The ordinary controller can replay the full recent turn history. The
resident-session transport instead receives a bounded working projection whose
items are shaped as lived public tuples: intention, expected consequence,
chosen action and arguments, a plain statement of whether Minecraft actually
accepted it, and coarse perception afterward. It carries no controller
`input`/`result` objects, historical camera grid, coordinates, target identity,
or provider-private reasoning. A missing commitment, policy mismatch, or
difference between the structure and public rendering fails trajectory
admission and replay; the complete Lync remains authoritative over this
disposable working view.

This reuses the existing own-loom observation, action, outcome, utterance, and
bounded-continuity seams. It does not reintroduce `manage_project`, injected
projects/places, or another project-management abstraction into the
human-semantic body. The legacy `resident-v1` project memory remains unchanged
for that separately named treatment.

## Treatment comparison

| Boundary                     | `neutral-benchmark-v1`            | `legible-resident-v1`                                    | `resident-v1`                                                                   |
| ---------------------------- | --------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Intended use                 | Minimal evaluation protocol       | Legible self-directed resident life                      | Coached continuing product resident                                             |
| Identity charter             | None beyond embodiment            | Persistent trajectory and public commitments             | Persistent entity and unfinished concerns                                       |
| Public response              | One action, no required statement | Intention + expected observable consequence + one action | Free-form public intention + tool call                                          |
| Goals or strategy            | None                              | None                                                     | Survival, learning, materials, shelter, social and action heuristics            |
| Project machinery            | Disabled                          | Not exposed on the human-semantic surface                | `manage_project`, project/place projections, completion rules                   |
| Behavioral controller guards | Disabled                          | Disabled                                                 | Repetition, failed-strategy, communication, and project-bookkeeping loop breaks |
| Human-semantic defaults      | Yes                               | Yes                                                      | No; resident body/action and safe-risk defaults                                 |

These are different treatments, not a quality ordering. Deterministic tests can
prove their prompts, schemas, persistence, and rejection boundaries; they
cannot prove that the legible treatment causes better Minecraft behavior.

## First live result and next gate

The first live acceptance used the already-exercised Oxford V3 admission, two
exact local model identities, ordinary event-driven life, a fixed four-minute
wall clock, and only high nonbinding attempt ceilings. Both residents were
bound to the same v2 treatment/body and their own prior Lync continuity. There
was no task/project injection, retry, correction, normalization, catch-up,
provider call, or operator action after release.

The treatment seam passed mechanically for Phi's two valid turns: each exact
public commitment, action, authoritative outcome, and safe current/next
perception persisted and rendered through Textile without exposing private
causal frames. Behavior remained red. Llama returned two malformed greetings;
Phi only reversed its view; the five-second urgent-decision boundary then
cancelled work much faster than either local model could answer while mobs
killed both bodies repeatedly. The exact result is recorded in
[Legible-resident Oxford acceptance](reports/2026-07-26-legible-oxford-acceptance.md).

Another schedule or larger attempt ceiling is not the next gate. A subsequent
no-world session probe preloaded both exact local models and moved the repeated
control catalog ahead of changing life, but concurrent decisions still took
14.5-24.5 seconds. It also caught and removed a controller-shaped continuity
projection that taught Llama the wrong response wrappers. The corrected
session mechanics are useful; the installed pair remains unsuitable for a new
ordinary-ecology acceptance at those measured latencies. The broader gate is a
resident cognition runtime with body-relevant latency, independently active
sessions, and the unchanged charter/action validator. A later run must still
observe behavior rather than assume either the charter or runtime causes it.
